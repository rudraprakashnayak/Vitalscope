The Interview Hook: Why Vitalscope?

⚠️

The Candidate Problem

Most computer science graduates study Operating System concepts (procfs, sysfs), C++ syntax, and Multithreading in complete isolation without ever seeing how they interact in a real production system.

⚡

The Engineering Solution

Vitalscope connects all 3 domains into 1 lightweight tool. It demonstrates end-to-end how raw kernel pseudo-files are parsed, safely converted into immutable C++ types, and rendered via asynchronous threads.

  • Zero External Dependencies: Written purely in standard C++17 and Linux POSIX system calls.
  • Unprivileged Execution: Safely inspects hardware state and process metrics without root privileges.

Multithreading & Signal Safety

Asynchronous Sampler Loop

The background `Sampler` thread uses `std::condition_variable` and `std::mutex` to poll pseudo-files periodically without blocking the main CLI interface. 

void Sampler::loop() {
    while (!stop_requested_.load()) {
        Snapshot snap = collect_all();
        {
            std::lock_guard<std::mutex> lock(mutex_);
            latest_ = snap;
        }
        cv_.wait_for(lock, interval);
    }
}

Polite Signal Handling

Intercepts `SIGINT` (Ctrl-C) and `SIGTERM` via atomic flags, waking the sampler condition variable, joining the worker thread, and returning exit code 0. 

static std::atomic<bool> g_stop{false};

void on_signal(int sig) {
    g_stop.store(true);
}

Engineering Highlight: --root Test Fixtures

The Testing Dilemma

Testing system tools against a live `/proc` filesystem causes flaky tests because system load, memory usage, and process lists change constantly.

The --root Solution

`fs_util` prepends a root directory parameter (`root_`) to all file paths. Passing `--root tests/fixtures` redirects file access to saved mock files. 

# Run deterministic tests on any machine (Windows, Linux, CI/CD) without a live kernel
./build/vitalscope --root tests/fixtures --once

Interview Viva Defense Q&A Cheatsheet

Q1: How do you calculate CPU usage % from /proc/stat?
`/proc/stat` counters are cumulative jiffies. A single read gives total time since boot. Vitalscope samples twice across a time window and calculates the delta in busy vs. total jiffies: Usage % = (ΔBusy / ΔTotal) * 100.
Q2: How do you parse process names that contain spaces in /proc/<pid>/stat?
Process names are enclosed in parentheses `(comm)`. Vitalscope finds the first `(` and the last `)` in the stat line to reliably isolate executable names with spaces.
Q3: How do you handle processes that exit while being enumerated?
When walking `/proc`, a process might terminate before its `/proc//stat` is read. `ProcCollector` catches the resulting `std::runtime_error` gracefully and skips that process without crashing.
